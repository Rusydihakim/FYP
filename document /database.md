# AthleteFit Pro — Database Architecture & Schema Specification

# Engine: PostgreSQL 15+ (Supabase) | Multi-Sport Core (Rugby Focus)

## 1. Architectural Overview & Entity Relationships

The AthleteFit Pro database architecture is structured around seven relational modules designed to support cross-platform operations (React Native mobile clients and Next.js web portals) with sub-second telemetry ingestion and row-level security (RLS).

```
[organizations] ──1:N──> [squads] ──1:N──> [squad_members]
      │                                           │
      └──1:N──> [organization_members] <─────────┘
                      │
[profiles (auth.users)]
      ├──1:1──> [athlete_profiles] ──1:N──> [athlete_injuries]
      ├──1:N──> [wearable_connections]
      ├──1:N──> [daily_readiness_logs]
      ├──1:N──> [athlete_telemetry_samples] (High-Frequency Streams)
      ├──1:N──> [scheduled_workouts] ──1:1──> [workout_execution_logs]
      │                                                └──1:N──> [workout_set_logs]
      └──1:N──> [chat_threads] ──1:N──> [chat_messages]

[training_programs] ──1:N──> [workout_templates] ──1:N──> [workout_template_exercises]
                                                                  │
                                                          [exercise_catalog]
```

## 2. Relational Module Breakdown

### Module 1: Organizations, Identity & Roster Management

* **`organizations`:** Stores club, academy, or franchise entities. Includes sport type and unique 6-digit invite code.
* **`profiles`:** Extends Supabase `auth.users` with display names, avatars, roles (`athlete`, `coach`, `head_coach`, `physio`, `admin`), and visual theme preferences.
* **`organization_members`:** Junction table defining role-based staff and player affiliations within clubs.
* **`squads`:** Sub-divisions within an organization (e.g., *First XV*, *Under-21s*, *Forwards Unit*, *Backline*).
* **`squad_members`:** Maps players to squads with positional titles and assigned jersey numbers.

### Module 2: Athlete Profile, Physical Biometrics & Safety Gates

* **`athlete_profiles`:** Stores core anthropometric baseline data. Automatically computes BMI and baseline maximum heart rate ($220 - \text{age}$) using generated columns. Encapsulates rugby-specific position groupings (`forwards` vs. `backs`) and equipment access arrays.
* **`athlete_injuries`:** Manages contact clearance and return-to-play (RTP) protocols. When an athlete reports a concussion or severe neck/joint pain, `contact_cleared` is set to `FALSE`, preventing high-collision exercise recommendations.

### Module 3: Wearable Ingestion, Telemetry Streams & Benchmarks

* **`wearable_connections`:** Secures OAuth access tokens, refresh tokens, and synchronization schedules for Apple HealthKit, Android Health Connect, Fitbit, WHOOP, and Garmin Connect IQ.
* **`daily_readiness_logs`:** Daily aggregated recovery metrics including resting heart rate, HRV (rMSSD), sleep duration, and subjective collision soreness scores.
* **`athlete_telemetry_samples`:** High-frequency time-series table logging timestamped pulse rates, heart rate training zones (1 through 5), active calories, and speed/distance.
* **`rugby_benchmarks`:** Stores performance fitness metrics like the standardized 1.2 km Bronco test time and 40m sprint splits.

### Module 4: Exercise Catalog & Positional Taxonomy

* **`exercise_catalog`:** Centralized database of movements indexed by target muscle groups, required gym/field gear, ExerciseDB API reference IDs, video demo URLs, and rugby positional bias (`forwards`, `backs`, or `neutral`).

### Module 5: Training Programs & Match-Week Microcycles

* **`training_programs`:** Multi-week structured blocks created by coaches or generated by AI models.
* **`workout_templates`:** Individual daily sessions mapped to match-week microcycles (`MD-4` Heavy Strength, `MD-3` Velocity/Speed, `MD-2` Taper, `MD-1` Captain's Run, `MD+1` Recovery Flush).
* **`workout_template_exercises`:** Prescribes sets, target reps, RPE (Rate of Perceived Exertion), % 1RM, and mandatory rest intervals.

### Module 6: Session Scheduling, Execution & Tonnage Logs

* **`scheduled_workouts`:** Calendar dispatch records matching athletes to specific template workouts on given dates.
* **`workout_execution_logs`:** Session summaries recording actual start/end timestamps, total tonnage lifted ($\sum \text{weight} \times \text{reps}$), peak heart rate, and high-speed running meters (>5.5 m/s).
* **`workout_set_logs`:** Granular set-by-set execution logs capturing actual reps completed, weight used, and recorded RPE.

### Module 7: Real-Time Chat & Video Form Feedback

* **`chat_threads`:** Connects an athlete to their designated head coach or trainer within an organization.
* **`chat_messages`:** In-app messages supporting video clip attachments with scrubbable timestamp markers for tackle/scrum form correction and coach verification tags.

## 4. Performance Indexes & Query Optimization

To sustain sub-second query latency during peak team sync windows (e.g., immediate post-training periods), composite B-tree indexes are declared on foreign keys and time-series axes:

* `idx_telemetry_athlete_time`: `(athlete_id, recorded_at DESC)` ensures instantaneous rendering of live telemetry ribbons and historical graphs.
* `idx_readiness_athlete_date`: `(athlete_id, log_date DESC)` powers daily morning recovery cards without table scans.
* `idx_scheduled_athlete_date`: `(athlete_id, scheduled_date)` enables instant match-week microcycle calendar loads.
* `idx_chat_thread_time`: `(thread_id, created_at ASC)` loads chronological message histories efficiently.

## 5. Security & Row-Level Security (RLS) Policies

All tables in the schema enforce PostgreSQL Row-Level Security (RLS) to guarantee complete data isolation between rival clubs and protect sensitive medical telemetry:

1. **Player Privacy Isolation:** Athletes can only read and write their own biometrics, telemetry samples, and workout logs:
   ```sql
   CREATE POLICY athlete_self_manage ON profiles FOR ALL USING (auth.uid() = id);
   ```
2. **Coach Squad Oversight:** Coaches and athletic staff can only access data for athletes who belong to their designated organization:
   ```sql
   CREATE POLICY coach_view_roster ON athlete_profiles FOR SELECT USING (
       EXISTS (
           SELECT 1 FROM organization_members coach_mem
           JOIN organization_members ath_mem ON coach_mem.organization_id = ath_mem.organization_id
           WHERE coach_mem.user_id = auth.uid()
             AND ath_mem.user_id = athlete_profiles.user_id
             AND coach_mem.role IN ('coach', 'head_coach', 'admin')
       )
   );
   ```
3. **Medical & Physio Access:** Concussion watch and injury records are restricted to the player and certified medical staff (`physio`, `head_coach`), maintaining compliance with medical data privacy regulations.
